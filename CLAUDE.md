# CLAUDE.md

Repository guidance for every coding agent.

## What this is

TaylorMade Agent Monitor is a Windows-only Electron + TypeScript + React tray app for local Claude Code and Codex activity, presented as a hotkey-summoned full-screen multi-pane workspace. It uses stable lifecycle hooks for live state, provider-qualified identities, provider-specific usage/value, optional MongoDB history, and native Win32 launch/focus for the terminals, editors, and browsers you drive agents from.

## Commands

```powershell
npm run dev
$env:CLAUDE_WATCH_MOCK=1; npm run dev
npm run typecheck
npm test
npm run build
npm run dist:dir
npm run dist
npm run publish
npm run hooks:install
npm run hooks:codex
npm run icons
```

`npm test` discovers every `*.test.mjs`; do not restore a hard-coded list. There is no linter, so typecheck, tests, build, and `git diff --check` are the normal gates.

## Architecture

```text
Claude/Codex/Cursor hooks -> hooks/bridge.mjs -> authenticated /v1/events -> AgentStore
Claude JSONL ledgers ---------------------------------------------> UsageAccount[]
Codex rollout parser (best effort, isolated) --------------------> UsageAccount[]
OAuth/Admin APIs ------------------------------------------------> UsageAccount[]
AgentStore + usage + history -> StatusSnapshot -> preload IPC -> React
```

- `src/shared/types.ts` owns provider-neutral contracts: `ProviderId`, `AgentEventV1`, provider-qualified `Agent`, `ProviderHealth`, `UsageAccount[]`, schema-v2 `DailyUsageDay`, and the mutable-only `AppSettingsPatch`.
- `src/main/store.ts` is the reducer. It deduplicates event IDs, rejects older actor events, keeps child identities separate, persists idle transitions, and prices each message with its original model.
- `src/main/daemon.ts` exposes exact authenticated loopback routes. Every route, payload, timestamp, enum, number, string, and cardinality is runtime validated. `GET /v1/status` returns the renderer's `StatusSnapshot` (via the `snapshot` option) for token holders — `scripts/tm.mjs status` reads the endpoint file and calls it. The agent-facing write surface is the terminal routes — `GET|POST /v1/terminals`, `POST /v1/terminals/:id/input`, `GET /v1/terminals/:id/output` — and the `GET /v1/agents/:id/wait` long-poll, all behind the `terminals` adapter (`TerminalApi`) main passes in; without it they 404. A terminal spawned this way is announced to the renderer as an `open` command carrying `sessionId`, so the pane *attaches* instead of creating its own shell, and stays headless (`attached: false`) when the grid is full. Only `output` and `wait` accept a query string. `agentForTerminal` (`attention.mjs`) names the session running in each terminal. `hooks/SKILL.md` (`tm skill --install`) teaches a session the routes and the etiquette (check status before starting a second session in a project; wait, don't poll).
- `hooks/bridge.mjs` is the shared short-lived Claude/Codex/Cursor bridge. It discovers port/token from the app-data endpoint file and performs one bounded request, stamping the event with `terminalId` when `TM_TERMINAL_ID` is in its environment (an embedded pane). It must never retry or fail the provider command. Cursor imports compatible Claude hooks, so Cursor-originated Claude compatibility invocations must be ignored to avoid duplicate sessions.
- `hooks/install.mjs` atomically merges/removes exactly-owned user hooks with backups. Claude and Codex use nested hook groups; Cursor uses direct version-1 handlers. Codex still requires the user to review trust in `/hooks`.
- `src/main/localUsageCore.mjs` keeps per-file/per-message Claude ledgers and performs serialized bounded full scans. Since 0.4.7 the ledgers, the Codex rollout scan, and the insights scan run in the **usage worker** — `src/main/usageWorker.ts`, a `utilityProcess` main forks lazily from `out/main/usageWorker.js` (a second main input in `electron.vite.config.ts`; it imports no Electron) — because those readers parse JSONL synchronously and a heavy transcript day hitched main, the IPC hub for six xterm panes and the 1 Hz snapshot. Main holds only the read side: `LocalUsageView` (same accessors as `LocalUsage`, answered from the `snapshot()` the worker returns after each `claude-refresh`; `today*` re-derive per call so a day rollover reads empty, not yesterday). `src/shared/usageWorkerProtocol.mjs` (tested) is the contract — `parseRequest`/`parseResponse` drop anything malformed, `PendingCalls` routes answers by id and fails every waiter when the worker exits — and `callWorker(kind, args)` in main adds a 60 s timeout per call. A dead worker is re-forked on the next call under the same `reloadBudget` as a renderer reload (three per five minutes); past that, the local account carries a `note` until the window passes. The worker is killed after the final history flush on quit, never before. Verified to fork from inside the asar (`npm run debug:app -- --packaged` with `CLAUDE_WATCH_SELFTEST=1` prints `todayOut=<n>` only if the worker answered).
- `src/main/codexUsage.mjs` is the only place allowed to understand unstable Codex rollout JSONL. Drift disables only Codex usage, never live hooks.
- `src/main/usageCore.mjs` parses Anthropic Admin usage/cost pagination, including decimal-string cents and UTC buckets.
- `src/main/history.ts` serializes Mongo operations, writes schema v2 `byProvider`, reads legacy documents as Claude, attributes API spend to its exact UTC date, and is optional/failure-isolated.
- `src/native/win32.mjs` loads system DLLs through koffi. Main resolves focus by agent ID and passes the stored PID so HWND ownership is checked before foreground calls.
- `src/renderer` groups roots by canonical cwd, nests children, renders provider badges/health/usage, and labels trends against real local calendar dates. Layout is the agent sidebar (agent list plus toggleable stacked data views) and a main pane grid of embedded terminals and the data panes (Agents, Spend, Insights, History, Activity — status bar → Panes, or User menu); `Escape` closes an open menu, the palette, or a dialog, then un-zooms a zoomed pane, otherwise hides the workspace — unless focus is inside a terminal pane, where Escape belongs to the CLI. Zoom (pane header button or double-click) hides the other panes with `display: none` rather than unmounting them, so a running shell is never disturbed.
- `src/main/terminals.ts` owns embedded terminal sessions: real ConPTY shells via `node-pty` (native, prebuilds, `asarUnpack`'d), bounded scrollback for reattach, killed on quit. The renderer side is `TerminalPane.tsx` (xterm.js); `term:*` IPC routes are validated like everything else. Sessions survive hide/show and pane remounts, never an app restart — but every shell runs `PROMPT_HOOK` (wraps the profile's prompt to emit the Windows Terminal `OSC 9;9;<cwd>` report; parsed by `lastCwdReport` in `terminalText.mjs`, announced as `term:cwd` only on change), so a pane persists the folder its shell is *in*, and a pane whose stored session id is stale after a restart respawns there with `resume: true` — and with the exact session when the pane knows it: the bridge stamps every hook event with the pane's PTY id (`TM_TERMINAL_ID` → `AgentEventV1.terminalId` → `Agent.terminalId`), `agentForTerminal` matches on it before falling back to folder — for *any* launch, because a CLI typed into a plain shell pane is still that pane's session (that is exactly how the first restart failed to resume: the panes were shells the user typed `claude` into, so nothing was relaunched) — App persists the matched `rawSessionId` as the pane's `resumeId` and flips the pane's `launch` to the provider (so the header says Claude Code and the restart resumes it), and main runs `claude --resume <id>` / `codex resume <id>` (else `--continue` / `resume --last`). `resumeId` is validated to `[A-Za-z0-9_-]{1,128}` at the IPC and in `sanitizePanes` because it is interpolated into the launch command. `claude attach <id>` is not the tool here: it opens a still-running background session, and the PTY died with the app. Every PTY gets `TM_AGENT_MONITOR_ENDPOINT_FILE` and `TM_TERMINAL_ID` in its environment (the `envFor` constructor argument) so a CLI inside a pane can find the daemon. Ctrl+V is handled in `TerminalPane` (`attachCustomKeyEventHandler`), not left to xterm: xterm turns Ctrl+V into the raw `^V` byte and cancels the event, so nothing pastes and the CLI sees its image-paste key — the pane reads the clipboard through `clipboard:read` and calls `term.paste` for text (one bracketed paste), and forwards an image-only clipboard as `^V` (Codex) or `ESC v` (Claude Code's Alt+V).
- The agent list lives in **one** place at a time: by default the sidebar's Agents section (under Limits, `SidebarView` 'agents', `tm.sidebar.v3` — a v2 sidebar migrates once and gains it via `surface`), or the Agents pane in the grid when the user opens that instead. `addPane('agents')` hides the section, `toggleSidebarView('agents')` on closes the pane, and a startup effect drops a persisted Agents pane when the section is on. The section's header carries the waiting filter and collapse-all tools; `defaultPanes()` is empty. Open windows left the sidebar in 0.4.4 — the palette's `#` prefix raises any window (`listWindows` is called once per palette open, never polled). `tm.panes.v3` is the pane key; `migratePanesV3` (tested) still puts an Agents pane in front of a v2 layout, and the startup effect then yields it to the sidebar.
- Colour carries one meaning each: red (`--st-question`) only for "a session needs you"; amber (`--st-permission`) for warnings; the `--pressure`/`--pressure-hot` ramp for resource fill (context %, quota bars) so a full context window never reads as a question; provider dots keep the saturated identity colours and `--st-running` stays quieter than them.
- `src/shared/panes.mjs` owns the *parsing* of every persisted layout key (`sanitizePanes`, `sanitizeSidebarViews` with the v1→v2 migration, `sanitizeCollapsed`, `readPaneCols`, `readAllSizes` with the pre-bucket seed) — pure and tested; `panes.ts` only reads/writes localStorage and holds the catalogs. `TerminalPane` is `React.lazy` in `App.tsx` so a workspace without a terminal never parses xterm.
- `src/renderer/src/panes.ts` owns the layout contract: main-frame panes are instances (`{id, kind}`, `MAX_PANES = 6`) — `agents`, `spend`, `insights`, `history` and `activity` unique, `terminal` repeatable with per-pane launch config; `PANE_ALIASES` maps a retired kind to its successor (`usage` → `spend`) and `sanitizePanes` applies it, so an old layout still opens something — plus the `SidebarView` catalog (limits only, since 0.4.4) toggled from the status bar's Panes popover — `SIDEBAR_TOP` pins above the agent list, the rest stack below, and each section rolls up to its header. Views, collapse state, panes, and the `tm.layout.v1` sizes all persist to localStorage; `tm.layout.v1` is read and written through one merge helper so a new size never drops an old one. Sizes (sidebar width, column fractions, row fractions) are stored per view bucket — `{sizes: {full, half}}` — because a split tuned for the full screen is wrong at half the width. The split row's launch preference is `tm.launch.v2` (`readLaunchPrefs` / `launchFor` / `withLaunch` in `panes.mjs`, tested): a global default plus a per-folder pick keyed by `launchKey` (slash- and case-insensitive), bounded to 50 folders; the v1 string migrates once.
- `src/shared/layout.mjs` owns the resize arithmetic — sidebar clamping (`clampSidebarWidth`, `defaultSidebarWidth`), track fractions (`normalizeFractions`, `resizeFractions` with a per-axis minimum, `columnTemplate`), and `viewportBucket` — as pure functions with tests, so nothing about a legal drag is decided in a component. `Splitter.tsx` is the handle: it reports pixels moved since pointer-down along its axis (pointer capture, arrow keys, double-click reset) and owns no geometry. Column and row splitters live in real gutter tracks, which is why pane slots are placed explicitly (`gridColumn`/`gridRow`) instead of auto-flowing, and why both grid gaps are 0 — the gutter *is* the gap. Drag start measures the used `grid-template-columns`/`-rows` rather than assuming padding and gap. `viewportBucket` reads the live viewport, never the persisted `sizeMode`, so the transient Alt+Q half view loads half-view sizes instead of overwriting full-view ones.
- `src/renderer/src/TopBar.tsx` is the app chrome as one IDE-style title bar: the brand mark (`assets/icon.png`, the tray icon) and the File / Terminal / User menus at the left, the command center in the middle, passive status (waiting count, connection health) and the two window controls at the right — minimize (`window:minimize`, a real minimize: the button stays in the taskbar and Alt+Tab, and `showWindow`/the hotkey `restore()` it first) and the close glyph, which hides to the tray exactly like Escape (`window:hide`; there is no quit button — quit is File → Quit and the tray). The connection chip reads `overallStatus` (`health.mjs`): `needsRepair` is checked *before* `installed` because the daemon only sets it with `installed=false`, so hooks written by another build (a stale bridge path, still reporting) read as **repair hooks**, never "no hooks" — the waiting chip *goes there*: click focuses the next waiting session (`routeToWaiting`, same as Ctrl+Shift+W), Shift-click is the list filter. There is no "while you were away" digest any more; the chip is what a cold return needs. **Menus hold verbs, the status bar holds state**: there is deliberately no View menu. `StatusBar.tsx` is the IDE-style bar under the frame — at the left the **Update** chip (`update-chip`, the same `app:reinstall` route as Settings → Rebuild & relaunch; App holds the shared `rebuild` busy/result state so the chip, File → *Rebuild & relaunch*, and the palette command never disagree), the **Panes** popover (opens/closes the unique panes and the sidebar sections) and the **Layout** popover (workspace size, columns, saved layouts, reset sizes; its chip label is the live state, `Full · Auto`), both held in App's `openMenu` as `'panes'`/`'layout'`; at the right the `CDP :port` chip and the version. File holds project verbs (new project, Projects folder, Open in Cursor, Open Chrome, reset order, rebuild, hide, quit); Terminal holds the launches agents-first, the external terminal, and **Run** (the folder's `.tm.json` commands then npm scripts, in a new pane); User holds Usage, Activity, Settings. Every app action lives in a menu or status-bar popover *and* the palette; the sidebar and panes stay pure content — do not reintroduce a wordmark row, a footer action strip, a top-right button cluster, or a View menu. Shared dropdown pieces (gliding-highlight `MenuPop`, `MenuItem`, `MenuCheckItem`) live in `Menu.tsx`.
- `src/renderer/src/CommandPalette.tsx` is the quick-open: every command (mirroring the menus, built in `App.paletteItems`), every root agent (focus), and every open window (raise), ranked by `src/shared/palette.mjs` (`fuzzyScore`, `rankItems`, `>`/`@`/`#` prefixes — pure, tested). It never shows the whole catalogue unasked: with nothing typed it lists only the `pinned` commands (the three launches, next waiting session) and the agents (`homeItems`) with a footer counting the rest; `>` alone browses every command under group headings (`browseItems`; `commandGroup` derives Start / Snippets / Run / Project / Panes / Layout / App from the command id — a new command id must match one of its patterns or it lands under Other); typing ranks everything flat. Ctrl+Shift+P always opens it; Ctrl+P too, unless a terminal pane has focus, where Ctrl+P belongs to the shell. The window keydown listener runs in the **capture** phase so app chords win before xterm swallows them; only Ctrl+Shift chords (palette, `` Ctrl+Shift+` `` new terminal) reach past a focused terminal. Escape order: context menu → snippet menu → menu → palette → dialog → un-zoom → hide. "menu" is App's single `openMenu` state — the title-bar menus *and* the launch nav's two popovers share it, so only one is ever open and none of them can fall through to hiding the workspace. Other app chords: Ctrl+Shift+W next waiting session, Ctrl+1…6 focus pane, Ctrl+Shift+←/→ step panes, Ctrl+, settings.
- `src/renderer/src/useNow.ts` is the only one-second clock: `useNow()` subscribes leaf components (agent rows, quota bars) to a shared interval. `App` must not hold `now` in state — that re-renders the grid and every xterm host every second. Anything new that prints a duration calls the hook itself.
- OS-level attention: `src/shared/attentionSignal.mjs` (`attentionTransition`, tested) decides from `(prev, next, muted, focused, visible)` what the tray badge, the taskbar button, and a flash do — the tray icon always carries the waiting count (`trayImageFor`, a red badge drawn into raw BGRA by `src/shared/trayBadge.mjs` because `nativeImage` decodes only PNG/JPEG and main has no canvas); the window is **not** `skipTaskbar` (since 0.4.7 — a workspace you clicked away from should come back from the taskbar like any window; hidden, it has no button and the tray is the app). Note what that flag did and did not do here: Electron on Windows implements it with `ITaskbarList::DeleteTab`, not `WS_EX_TOOLWINDOW`, so a *visible* workspace was already in Alt+Tab (probed 2026-09-15 with the shell's eligibility rule against a 0.4.6 window) — dropping the flag adds the taskbar button only. So while it is visible the taskbar button carries the count as an overlay (`setOverlayIcon`, set only when it changes) and `flashFrame` once on the 0→N edge unless focused or muted — mute silences the flash, never the count. `win.on('focus')` stops the flash. Do not reintroduce `skipTaskbar`/`setSkipTaskbar`. `src/shared/pauses.mjs` (`tickAllowed`, `isWake`, tested) gates every background interval through `whenActive` on the `powerMonitor` lock/suspend state, and a wake runs one immediate refresh; `providerHookStateCached` re-parses a hook config only when its mtime moves (the 1 Hz snapshot used to parse three files a second), cleared by `hooks:manage`. `src/shared/crashPolicy.mjs` (`reloadBudget`, tested) bounds the automatic `webContents.reload()` on `render-process-gone` / a 10 s `unresponsive` to three per five minutes, then a notification whose click reloads; panes reattach to their PTYs by stored session id so shells and scrollback survive a renderer death. `windowMaterial` ('none' | 'mica' | 'acrylic', default mica) is a mutable setting: `backgroundMaterial` at creation, `setBackgroundMaterial` live, and `window:material` tells the renderer to set `data-material` on the root so the `.app` card goes translucent (Windows 11 22H2+; a no-op elsewhere).
- `src/shared/attention.mjs` (`paneForAgent`, `nextWaiting`, `waitingFirst`) and `src/shared/health.mjs` (`providerStatus`, `overallStatus`) are pure and tested; the pane bell badge, Ctrl+Shift+W, the palette's waiting-first order, the connection chip, and the Settings hook rows all read from them so they cannot disagree. `ConnChip` (TopBar) ticks with `useNow` so "silent for 12m" stays true between snapshots.
- Interactive elements carry `data-testid` from `src/renderer/src/testid.ts` (`tid('menu', label)`, `pane-tool:<title>`, `pane:<kind>:<index>`, `agent:<id>`, `splitter-col-<i>`…). Automation targets those, never class names. `--remote-debugging-port` surfaces as `AppSettings.debugPort` and the status bar's `CDP :port` chip.
- `src/shared/history.mjs` (`historySeries`, `modelMix`, `dayKey`) shapes `history:recent` for `HistorySection` — the only consumer of `getHistory()`. Days are laid on the local calendar, zero-filled, so bars line up with dates; legacy rows without `byProvider` count as Claude. `src/renderer/src/layouts.ts` owns `tm.layouts.v1`: a saved layout strips terminal `sessionId`s and restores fresh pane ids, and applying one disposes the open shells first.
- `AgentStore` keeps a 300-entry ring of attention moments (`recentEvents()`: root starts, waits from any actor, root turn completions, compactions, ends) served by `agent:events` for the Activity pane; mock mode serves `mockEvents()`. `src/shared/workspaceCommand.mjs` parses `tm …` argv for the `second-instance` handler and re-validates in the renderer (`onCommand`) — a plain second launch still just toggles the window. Phone push (`pushUrl`, `pushAfterMin`) follows the mutable-setting checklist; `checkPush` runs once a minute and posts each waiting root session once.
- Per-folder IPC: `project:commands` (parsed by `src/shared/projectCommands.mjs` from `.tm.json` + `package.json`, bounded) and `git:status` (`src/shared/gitStatus.mjs` parses `git status --porcelain=v1 -b`; main caches 30s, 4s timeout). Both validate that `cwd` is an existing directory and never throw to the renderer. `useProject.ts` polls them visibility-gated. A `TerminalPaneConfig.initialCommand` is typed once into a freshly created shell, never on reattach.
- `src/renderer/src/Pane.tsx` is an editor-title bar, not a content picker: kind icon + title (a terminal pane's title is what it runs — Claude Code / Codex / Terminal — via the `title` override; there is no chip), the pane's full **live** folder (`path`, ellipsised from the left so the tail stays readable — a terminal pane passes `term.cwd`, which `term:cwd` keeps current), then a per-kind tool strip (`tools`) before zoom and close. Clicking the path copies it (`text:copy`) and flashes *Copied*. The focused pane tints its own border (`.pane-slot.is-focused > .gpane`), not an inset shadow — the body painted over that so only the header edge showed. The terminal strip is deliberately tiny — `/compact` when context is hot, then zoom and close (4.3-plan.md item 5): snippets are the palette's **Snippets** group acting on the focused terminal pane, split is Terminal → New terminal, clear is Ctrl+L, restart is close-and-reopen, external terminal / open folder are per-agent palette items. Do not grow the strip back. A pane's kind is fixed for its life — swapping a terminal into a launcher would kill its shell, so a different kind is a new pane. `TerminalPaneHandle` (`clear`, `restart`, `focus`) still exists via `forwardRef` for the palette's use.
- `src/renderer/src/LaunchNav.tsx` is the head of the sidebar: a launch-target switcher (follow the active session, home, or any live project — or a folder dropped from Explorer, resolved by `path:describe`) over up to three **recent-project chips** (the other live projects, newest first — one click retargets; hidden when there are none) and one **icon row** (`.navicons`: Claude Code, Codex, terminal, then New project at the right — the activity-bar shape; the folder's usual launch sits on a square, `is-usual`). Starting from an icon records it as that folder's usual launch (`tm.launch.v2`); Shift-click opens an external window. The switcher popover holds the same starts with names under a **Start in <folder>** group after **Follow** and **Live projects**, plus *New project…*. There is no split launch row and no `launch-pick` popover any more — `NavMenu` is just `'launch-target'`. Nothing else: Open in Cursor, Open Chrome, and the Projects folder are File-menu verbs (and palette items), and the folder's `.tm.json`/npm commands are Terminal → Run and the palette's `Run:` items. The switcher popover groups **Follow** (active session, home) and **Live projects** (name over full path, so two projects sharing a name stay distinct; the list is deduped by `launchKey`) — the nav is the launch path only (see `4.2-plan.md`). The palette and the Terminal menu keep three distinct commands and do not move the folder's usual launch; `` Ctrl+Shift+` `` always opens a plain shell. The popover is held in App's `openMenu` (see `NavMenu`), not local state. Starting something is navigation, not work: there is no launcher pane, the grid holds only work, and `defaultPanes()` is empty (the grid shows an empty state instead of spawning a shell). A dropped `File` becomes a path through `webUtils.getPathForFile` in the **preload** — `File.path` was removed in Electron 32 and the sandboxed renderer never sees the object.
- Terminal launches open embedded panes (Shift-click for an external window, and a full grid degrades to external). Open windows are palette items only (`#`), fetched once per palette open. The Agents pane's empty state is the first-run path: when no provider's hooks are installed it offers *Install Claude Code hooks* / *Install Codex hooks* (the same `hooks:manage` IPC as Settings) with the result inline.
- Panes render this app's own content — the embedded terminal is our xterm over our PTY, not a captured window. Electron cannot host a foreign native window (electron/electron#10547 is open with no API), and reparenting a live HWND via `SetParent` breaks input/focus/DPI in the captured window — so the switcher raises real windows instead (Cursor stays launch-and-focus). `WebContentsView` (Electron 30+) is the supported route if a pane ever needs embedded *web* content.
- `src/shared/windows.mjs` is the pure classification layer: which executables the switcher shows, their display names, title cleanup, and grouping. `src/native/win32.mjs` only reads Win32 and stays dumb about presentation.
- `src/renderer/src/NotesPane.tsx` is the **shared notepad** (unique pane kind `notes`, status bar → Panes, palette *Notes*, `tm notes`): a list of Markdown files in `config.notesDir` (`TM_NOTES_DIR`, default `%USERPROFILE%\Notes`) and a plain textarea for the selected one — the file on disk is exactly what is on screen, and an agent in a shell reads and writes the same files (`hooks/SKILL.md` tells sessions where it is). The header's **Preview** toggle (remembered in `tm.notes.preview`) swaps the editor for `MarkdownView.tsx`, which renders the tree from `src/shared/markdown.mjs` (`parseMarkdown`, tested) as React elements — never `innerHTML`, because a note may have been written by an agent: tags are text, and only http/https/mailto links survive, opened through `shell:open-external` (validated again in main). Edits save themselves 600 ms after typing stops (Ctrl+S now; atomic tmp + rename), the header path is click-to-copy, and the header tools are New note / Open folder (via a `NotesPaneHandle`). Main watches the folder (`ensureNotesDir`, one debounced `notes:changed` per burst) so an agent's write refreshes the list and, when the editor is clean, the text. `src/shared/notes.mjs` (tested) owns what a note name is — `isNoteName` is one `.md` segment, checked on both sides of the IPC because it becomes a path — plus `nextNoteName` (today's date, suffixed until free), `noteNameFor`, `sortNotes`, `notePreview`. Bounded: `MAX_NOTES`, `MAX_NOTE_BYTES`.
- `src/renderer/src/SessionField.tsx` is the **session field** (since 0.4.8): a WebGPU canvas the size of the sidebar, under its content (`.field`, `z-index: -1` in the card's stacking context — deliberately no `isolation` on `.sidebar`, which would trap its popovers under the grid), that washes the sidebar's background with one broad, faint light per session: the provider's colour, drifting and breathing while it runs, stiller and dimmer when idle, `--st-question` red and pulsing when it waits on a person, plus a burst on the edge into waiting. It is **atmosphere, not outline** — the first cut drew a halo per row and the user called it "a little crazy"; the intensities in `glowFor` are a fraction of that and the lights span most of the sidebar's width, so do not tighten them back onto rows. It is the tray badge's signal while the workspace is up, and it adds information, not chrome — keep the colour rule. What is drawn is decided in `src/shared/sessionField.mjs` (pure, tested): `glowFor` (state → colour/intensity/motion/pulse), `trackFlares` (the 0→waiting edge, `FLARE_MS`), `fieldGlows` (sessions → lights, waiting first under `MAX_GLOWS`: anchored at the row's height when that row is on screen, else even slots down the sidebar, so the wash never depends on the agent list being in the sidebar at all), and `packField`, whose layout is exactly the uniform `field.wgsl` declares — change one, change both. The component only measures the rows (`[data-testid^="agent:"]`, clipped to the agent list's scroll viewport so a row under the launch nav anchors nothing), uploads the buffer, and runs the loop: ~15 fps, only while the workspace is open (`active` = `open && fieldOn`) and the document visible, parked when there is no session, static under `prefers-reduced-motion`. No `navigator.gpu`, no adapter, a failed pipeline, or a lost device (one retry) leaves the canvas empty and everything else unchanged — `data-state` on the canvas says which (`on` / `idle` / `off` / `unsupported` / `lost`). The `@vgpu/core` wrappers (`Device`, `Buffer`, `bind`, the bind-group helpers) are what vgpu contributes; `@vgpu/wgsl/loader-vite` in the renderer's Vite plugins turns `field.wgsl` into a `{ wgsl }` module (the ambient types come from `vite-env.d.ts`, with `@webgpu/types`). Toggle: Layout popover → *Session glow*, palette *Session glow: on/off* (`cmd:field`, Layout group), `tm.field.v1` in localStorage; there is no main-side setting because main never needs the value. Cost: `+51 KB` minified on the renderer bundle, one 1.2 KB uniform write and one fullscreen triangle per frame at half resolution.
- `src/renderer/src/usageShared.tsx` owns provider grouping for usage: fixed provider order, accounts sorted plan → local → API spend, and the shared quota bar. `UsageDashboard` renders limit bars only (the sidebar's Limits); `SpendView` owns token counts, per-project breakdowns, and budget/actual spend. `UsagePane.tsx` exports the three data panes `SpendPane` / `InsightsPane` / `HistoryPane` (one view each, unique pane kinds picked from status bar → Panes) — none is reachable from the sidebar, and must not be: pane uniqueness is what keeps a second `UsageInsightsView` from doubling the local session scans.

## Configuration

`src/main/configCore.mjs` is the only bootstrap. It must run before constructing usage, history, daemon, or provider services. Precedence:

1. process environment;
2. Electron `userData/.env` (canonical installed config);
3. legacy `%APPDATA%/claude-watch/.env`;
4. project `.env` in development only.

`--mock` has highest precedence. Do not add module-scope environment reads back into provider services.

The daemon publishes `%APPDATA%/taylormade-agent-monitor/hook-endpoint.json` by default. Custom ports belong there; hook processes must not depend on inherited environment state.

Settings → "Rebuild & relaunch" (`app:reinstall`, also the status bar's Update chip) is the dev loop without a release: it runs `npm run dist` in the local checkout (`CLAUDE_WATCH_REPO`, default `~/Projects/claude-watch`), then a PowerShell waiter — created through WMI `Win32_Process.Create`, **never** as our own child: Electron's main process sits in a Windows job object and a `detached` spawn inherits it, so a child helper is killed the instant the app exits and the installer never runs (probed 2026-09-08) — waits for the app to exit and runs the built NSIS installer with `--updated /S --force-run` — the exact arguments `electron-updater`'s `NsisUpdater` passes on `quitAndInstall({ isSilent: true, isForceRunAfter: true })`, so the silent install relaunches the app itself, as the user, without anyone knowing the install directory. `scripts/reinstall-local.ps1` is the same flow from a terminal. Packaged builds only; the auto-update feed stays the release path. Do not reintroduce a hard-coded install path or a manual `Start-Process` of the exe.

## Agent tooling

- **Use the `electron-debug` MCP tools first** (`get_electron_window_info`, `take_screenshot`, `send_command_to_electron`, `read_electron_logs`) for anything about the running app — verifying a change, checking what rendered, clicking through a flow, reading console output. Start the target with `npm run debug:app`, confirm with `get_electron_window_info`, then drive it: `get_page_structure` to see what is clickable, `click_by_text` / `click_by_selector` / `fill_input` / `send_keyboard_shortcut` to act, `take_screenshot` to see the result. At the configured `SECURITY_LEVEL=balanced`, `eval` runs code but reports only `executed` — use it for actions, and read state through `get_page_structure`, `get_body_text`, or a screenshot. `fill_input` sets the DOM value without an input event, so React-controlled inputs (the palette) ignore it — `eval` the native value setter (`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set.call(el, text)`) then dispatch `new Event('input', { bubbles: true })`. Give `take_screenshot` a relative `outputPath` or none (absolute Windows paths are rejected). `send_keyboard_shortcut` does not reach window-level listeners (Escape did nothing) — for app-wide keys use `eval` with `window.dispatchEvent(new KeyboardEvent('keydown', { key: 'Escape', bubbles: true }))`, which does.
- Electron ships no official MCP server, agent skill, or `llms.txt`; `electron/electron`'s `.claude/skills` are maintainer workflows (Chromium/Node upgrades, PR triage), not app guidance. Do not answer packaging or updater questions from memory: the shipped source is authoritative — `node_modules/electron-updater/out/NsisUpdater.js` and `node_modules/app-builder-lib/templates/nsis/*.nsh` are where the reinstall flags above came from.
- `.mcp.json` registers that server (`electron-mcp-server`, CDP-based) via `scripts/mcp-electron-debug.mjs`, not `npx`: the package's entry has no shebang, and with npm's `script-shell` set to Git Bash here the bin shim sources the webpack bundle and dies on line 1 — the wrapper requires the package's main under node (devDependency first, else the npx cache through `npm exec`). It attaches to an app started with `--remote-debugging-port`; `npm run debug:app` launches the built app that way (mock data, throwaway `--user-data-dir` because the single-instance lock is app-scoped, daemon port 7460, and it strips `TM_AGENT_MONITOR_ENDPOINT_FILE`/`TM_TERMINAL_ID` from the environment — run from inside one of the installed app's panes, an inherited endpoint path made the debug app publish *its* port over the installed app's file and hijack every hook on the machine). Prefer it over hand-rolled `webContents.sendInputEvent` probes for verifying interaction.
- Repo skills live in `.claude/skills/` (`electron`, `workspace-layout`); the invocable copies are `~/.claude/skills/`. After editing a repo copy, `cp -r .claude/skills/<name>/. ~/.claude/skills/<name>/`.

## Invariants and gotchas

- Pure ESM. `electron-updater` is CommonJS: import its default and destructure.
- Unknown models have no value estimate. Never fall back across providers.
- Actual Anthropic organization spend stays separate from estimated agent value.
- `Stop` completes a turn; only `SessionEnd` removes a root. `SubagentStop` affects only its identified child.
- Provider hooks are the live authority. Private SQLite, experimental App Server, and OTel are not v1 dependencies.
- The renderer is sandboxed. Expose the smallest preload API and runtime-validate mutable IPC.
- `koffi` and `node-pty` remain `asarUnpack`'d. Packaged hook resources and native focus resources must stay in `electron-builder.yml`.
- Icon generation is offline and deterministic: `scripts/build-icon.mjs` derives ignored `build/icon.ico` from tracked `resources/icon.png`. Distribution commands run it automatically.
- The window covers the work area of the cursor's display (`positionWorkspace`) — full, or one half of it at full height per the persisted `sizeMode` setting ('full' | 'left' | 'right'), which is also the side the transient Alt+Q half view uses. Bounds never track content: there is deliberately no content-size IPC, no `setContentSize` call, and no renderer `ResizeObserver`. The edge-pull gesture (since 0.4.7) does not resize either: a transparent frameless window has no OS resize border on Windows (`resizable: true` + `will-resize` never fired — probed 2026-09-15), so the handle is the renderer's `EdgeGrip` strips (8px, `.edge-grip`, down each side of the card). A grip reports once per pointer-down, when the pointer has travelled `EDGE_COMMIT_PX` — `window:edge-drag` (edge, delta) — and main's `commitEdgeDrag` asks `src/shared/edgeDrag.mjs` (`edgeDragTarget`, tested) whether that commits: pull the left half's right edge out and the mode flips to full, pull a full workspace's edge inward and it becomes the half on the far side. The flip goes through `applySizeMode`, persists like a Layout-popover pick, and is pushed back as `window:size-mode` so the chip says what is on screen; the effective mode fed to the helper is what is on screen (`viewMode`/`halfSide()`), not the pref. Do not let a drag set bounds directly. The `.app` card fills the window and each scroll region (`.pane-scroll`, `.gpane-body`) absorbs its own overflow; the grid's column count is capped in `colCap()` (App.tsx) and the sidebar width in `clampSidebarWidth` (`@shared/layout.mjs`), never by media queries, so an explicit choice (View-menu columns, a dragged width) composes with the viewport instead of being silently overridden. Do not reintroduce content-driven window sizing, and keep the single `resize` listener the only measurement — it fires on real bounds changes only.
- Show/hide is animated in the renderer, not by moving the window. Main shows first and sends `window:phase` `enter`; on hide it sends `exit` and hides after `EXIT_MS` via a timeout that fires even if the renderer never responds. The `.app` card transitions a `translateY` — an animated `setBounds` loop is not smooth on Windows and must not replace it.
- The workspace is deliberately not always-on-top: anything it launches or focuses (`agent:focus`, `windows:focus`, terminal/Cursor/Chrome/Explorer) simply appears in front while the workspace waits behind — no route hides it. The hotkey raises a visible-but-buried workspace and only dismisses one that is already focused. Do not reintroduce `alwaysOnTop` or launch-time hiding (`stepAside`).
- Releasing requires the tag **and** the GitHub release to exist before `npm run publish`. electron-builder starts one publisher per artifact; they race to create the release, the loser returns 422, and that abort skips the `latest.yml` upload — leaving installers with no update feed. Re-running publish against an existing release uploads all four assets and overwrites the binaries so feed and exe stay consistent. Verify with `gh release view <tag> --json assets`; never trust the exit code through a pipe.
- Tags in this repo are lightweight. `tag.gpgsign=true` makes even a bare `git tag` fail on a passphrase-protected key, so use `git tag --no-sign`.
- MongoDB absence/failure must never block live monitoring. Quit performs a bounded awaited final flush.
- Verification commands may create ignored output, but must not modify tracked files.
