# 4.3 plan — the launch path, one click shorter

Follow-on to `4.2-plan.md`. Same rules: checkboxes are the source of truth;
update them as work lands. The journey has not changed — summon, point at a
project, start an agent, work, answer what is waiting — so every item below is
judged by one question: does it shorten that path or remove something from it?

Agreed 2026-09-08 from the 4.2 suggestion list, with two changes: the away
digest is **removed** rather than made actionable (a cold return is rare, and
the waiting chip already covers it), and two new items came from looking at the
terminal pane header (the tool strip diet, and the path in the title).

## 1. The waiting chip goes there

**Now:** the red `2 waiting` chip in the title bar toggles a *filter* on the
Agents pane. You click it because you want to answer someone, then you still
have to find and click the row.

**Change:** click = go to the next waiting session (exactly what Ctrl+Shift+W
does: `routeToWaiting`, which focuses the pane or raises the window). Shift-click
= the filter, for the rare "show me only these". The chip's title says both.
The tray tooltip's "N waiting" gets the same click.

**Where:** `TopBar.tsx` (`.needs` button: `onClick` → `onRouteWaiting`, `shiftKey`
→ `onWaitingOnly`), `App.tsx` passes `routeToWaiting`. The Agents pane keeps
its own filter tool. Palette already has *Go to next waiting session*.

**Done when:** one click on the chip lands you in the waiting session's pane (or
its window), and the list is never filtered by accident.

## 2. Launch choice remembered per project

**Now:** `tm.launch.v1` is one global default. A project you always run Codex in
still starts Claude Code when the row is clicked, because the last thing you
picked elsewhere was Claude Code.

**Change:** key the default by the target folder: `tm.launch.v2 =
{ default: TerminalLaunch, byCwd: Record<canonicalCwd, TerminalLaunch> }`.
Picking from the split row's popover writes both `default` and `byCwd[cwd]`.
The row reads `byCwd[cwd] ?? default`. Home folder (no cwd) uses `default`.

**Where:** `src/shared/panes.mjs` gets `sanitizeLaunch` (pure, tested: v1 string
migrates to `{ default }`, unknown cwds dropped, bounded to 50 entries);
`panes.ts` `loadLaunch`/`saveLaunch` become cwd-aware; `LaunchNav` takes the
resolved kind, `App` resolves it from `context.cwd`.

**Done when:** switching the target between two projects flips the row's label
without a click, and a fresh install still starts Claude Code.

## 3. Recent projects inline under the switcher

**Now:** the switcher is a dropdown; every project change is two clicks.

**Change:** a single row of up to three small chips under the switcher — the
most recent *other* live projects (from the agent list, newest activity first),
excluding the current target. One click retargets. The dropdown stays for
everything else (home, dropped folders, the full list). Hidden entirely when
there is nothing to show, so a one-project day costs no space.

**Where:** `LaunchNav.tsx` (a `recent: LaunchTarget[]` prop and a `.navrecent`
row of `.navchip`s), `App.tsx` derives `recent` from `groups` ordered by last
activity. No persistence — it is derived from live sessions.

**Done when:** with three live projects, moving between them is one click each.

## 4. The terminal pane title shows the live path, and clicking copies it

**Now:** the header reads `TERMINAL  [claude-watch]` — the launch chip shows the
folder *name*; the full path only appears on hover. Main now tracks the shell's
live cwd (`term:cwd`), but the header still shows where the shell *started*.

**Change:** the header becomes `TERMINAL  [claude-watch]  C:\Users\TC933\Projects\claude-watch`:
the chip keeps the short name (and the launch — `claude · claude-watch` when a
CLI was started), the path is printed after it in the muted title colour,
ellipsised from the left so the tail (the part that changes) stays visible.
Both the chip and the path are click-to-copy: one click writes the path to the
clipboard (`text:copy`, already an IPC) and the chip flashes `Copied` for a
second. No hover needed to see it, no dialog to copy it.

The path is the *live* one (`term.cwd` as updated by `onTermCwd`), so a shell
that has `cd`'d away says so. Same treatment for the Agents pane rows' project
headers later if it earns it; not in this pass.

**Where:** `Pane.tsx` gains `path?: string` and `onCopy?: () => void` (the chip
and the path share one handler); `App.tsx` passes `term.cwd`; a tiny `useCopied`
hook for the flash. `data-testid="pane-path"`.

**Done when:** every terminal pane shows its full current folder without hover,
and clicking the chip or the path puts that path on the clipboard.

## 5. Terminal pane header diet

**Now:** seven tools before zoom and close — split, snippets, clear, restart,
external terminal, open folder, and (when context is hot) `/compact`. Nobody
could say what the icons do without hovering; only zoom and close get used.

**Change:** the strip is `[/compact when hot]  zoom  close`. The `/compact`
prompt stays because it is conditional and it is the one that saves a session.
Everything else goes, and where it goes:

| Tool | Goes to |
| --- | --- |
| Split (another terminal here) | Terminal menu → *New terminal* already opens in the current target; nothing lost. |
| Snippets (type a command) | Palette group **Snippets** (`Snippet: …`), acting on the focused terminal pane; the catalogue in `snippets.ts` is unchanged. |
| Clear | `Ctrl+L` / `cls` in the shell. Not replaced. |
| Restart the shell | Close the pane and start another. Not replaced. |
| Open external terminal here | Palette per-agent item *terminal here* and Terminal menu → *Open external terminal* (both exist). |
| Open this folder in Explorer | Palette per-agent item *open folder* (exists); the new click-to-copy path covers "I just want the path". |

**Where:** `App.tsx` terminal `tools` (delete five `tool(...)` calls and the
snippets `MenuPop`), `snippetsFor` state goes away, palette gains the Snippets
group (`commandGroup`: `snippet:` → `Snippets`). `TerminalPaneHandle` keeps
`clear`/`restart` for the palette if wanted later; not exposed now.

**Done when:** the header has at most three tools and each is self-evident.

## 6. Remove the away digest

**Now:** after a long hide, a "While you were away — …" strip appears under the
title bar with a *Go to <project>* link. It fires rarely, and when it does the
waiting chip already says the same thing.

**Change:** delete it. `src/shared/digest.mjs` + `.d.mts` + test, the `away`
ref, `digest` state, the effect that clears it, the `.digest` block in `App.tsx`,
the `.digest*` CSS, and its CLAUDE.md sentence. Item 1 is the replacement: come
back cold, the chip says `2 waiting`, one click takes you there.

**Done when:** `grep -ri digest src` returns nothing.

## 7. Drop Open windows from the sidebar

**Now:** a collapsed-by-default section that polls `windows:list` when open. The
palette's `#` prefix already raises any window, and the switcher is where
Cursor/Chrome/terminals get raised anyway.

**Change:** remove the `windows` sidebar view. Limits becomes the only sidebar
view, so the Panes popover's second group shrinks to one toggle (keep the group;
it is still "sidebar"). `sanitizeSidebarViews` drops a persisted `windows`
silently. `WorkspacePanes.tsx` keeps `useDesktopWindows` for the palette's
window items only — visibility-gated as now.

**Done when:** the sidebar is nav + Limits, and `#` in the palette still lists
every window.

## 8. First-run state that offers the hooks

**Now:** with no hooks installed the Agents pane is simply empty and the grid
hint talks about starting a session — which then never shows up.

**Change:** the Agents pane's empty state checks hook health (`providerStatus`
already knows "never heard from"): if no provider has ever reported, it says so
and offers **Install Claude Code hooks** / **Install Codex hooks** buttons that
run the same `hooks:manage` IPC Settings uses, with the result inline. Once any
event has arrived the normal empty state returns.

**Where:** `App.tsx` agents pane body, reusing `SettingsPanel`'s `manageHooks`
logic moved into a small `useHooks` hook so both share it.

**Done when:** a fresh install shows a two-button path to a working monitor.

## 9. Settings as a status-bar popover (later)

Hotkey, startup, notifications, size are state; hooks, diagnostics, and the
reinstall are actions. A fourth status-bar popover (**Settings ▴**) for the state
half, leaving the modal for the action half. Do this last; it is the least
urgent and touches the most.

## 10. Panes resume their exact session (added 2026-09-08, shipped in 0.4.3)

`claude --continue` resumes the most recent conversation *in the folder*, so two
panes in one project would both come back as the same chat. The hook bridge now
stamps events with the pane's PTY id (`TM_TERMINAL_ID`), the store keeps it on
the agent, `agentForTerminal` matches on it first, the pane persists the matched
session id as `resumeId`, and the restart runs `claude --resume <id>` /
`codex resume <id>`. `claude attach <id>` was considered and rejected: it opens a
still-running background session, and the pane's process died with the app.

## Sequence

Value over effort, and each step leaves the app shippable:

1. Item 6 (remove digest) — deletion, ten minutes, clears ground.
2. Item 1 (waiting chip) — one handler, biggest daily win.
3. Item 5 (header diet) — deletion plus a palette group.
4. Item 4 (path in title, click-to-copy) — small, pairs with 5.
5. Item 7 (drop Open windows) — deletion plus a migration.
6. Item 2 (per-project launch) — pure parser + storage, tested.
7. Item 3 (recent chips) — nav change.
8. Item 8 (first-run hooks) — needs the hook logic hoisted.
9. Item 9 (settings popover) — only if the rest lands clean.

Steps 1–4 shipped as 0.4.3 (with the Limits diagnostics). Bump to 0.4.4 when the next batch lands so the version chip
moves; every step is verified with the electron-debug MCP before it is ticked.
